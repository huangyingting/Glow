# 霁光 PRO · 风光摄影天气地图

霁光是一个地图优先的风光摄影决策工作台。用户可以搜索城市、使用浏览器定位，或直接在中国地图上点击/拖动观测点；系统会为该坐标重新获取 168 小时专业气象数据，并计算霞光、雾景、太阳、月亮、星空、食象、云层、降雨和彩虹窗口。

## 当前摄影场景

- 朝霞 / 晚霞：低、中、高分层云量、降水、湿度、能见度、气溶胶和双模式一致性。
- 雾景潜势：露点差、相对湿度、低云、能见度、风速与非降水信号；因为尚未接入精细地形和水面距离，不把结果称为确定性的平流雾预报。
- 日出 / 日落：蓝调、黄金时段、日照长度、日出日落方位线。
- 月相 / 月升：按所选日期和当晚最佳小时计算照明、月相、月升月落、高度、方位与双模式天气机会，不再复用“当前月亮”。
- 星空 / 夜景：天文黑夜、三层云量、月光、降水、结露、能见度与阵风共同评分；明确不包含光污染、地形地平线和银河构图。
- 月食：为定位点搜索下一次峰值位于地平线上的食象及开始、食甚、结束时间。
- 日食：本地遮掩比例、太阳高度和接触时间；界面包含太阳滤镜安全提示。

## 天气分析工具

- 云层：找出每天总云量峰值，同时对照低、中、高三层结构和双模式分歧；分数就是云量百分比，不代表“好天气”。
- 降雨：结合预报概率、连续性雨、阵雨、实际量级和 WMO 天气代码形成综合信号；CMA 缺少降水概率时保留空值，不把信号写成概率。
- 彩虹：寻找降水/阵雨、直射阳光和 0–42° 太阳高度同时成立的小时，并给出反太阳观察方位。单点网格无法定位雨幕，因此结果只称“彩虹潜势”，不承诺可见。

专业变量被压缩为地图、七天机会带和右侧检查器：默认先给结论，随后是云层剖面、逐小时气象图、关键贡献、模式分歧和与拍摄时刻对齐的现场简报。检查器使用统一的 Compact 仪表板网格，不通过缩小正文换密度：宽屏将云层、贡献、模式等微型图表双列编排，窄手机回到单列；贡献解释放进可聚焦 hint，方法限制保留标题并渐进展开。简报用四个图标数据单元呈现阵风、来风方向、露点差、气压和海拔。食象不再伪装成七个相同的日分数，而是显示唯一事件、距离与是否进入天气预报窗口。

十个工具由一个注册表驱动，共享坐标、所选日期、数据生成时间、地图、七天带、来源披露与错误恢复。切换工具不会离开页面、丢失观测点或重复请求同一份天气；桌面使用左侧工具轨，移动端使用可横向滚动的同一工具轨。新增雷暴、风、雪或空气质量时，可继续插入计算器与检查器面板，不需要复制页面结构。完整设计见 [`docs/weather-tools-architecture.md`](docs/weather-tools-architecture.md)。

运行状态也直接呈现：数据源指示器显示真实的在线源数量，当前落点可手动刷新；无效城市、区域外落点和上游故障会给出可恢复的明确反馈，失败的地图落点会回滚标记。页面提供跳转链接、键盘可滚动图表、实时状态播报、错误与 404 页面；生产响应使用逐请求 nonce CSP、安全响应头和非缓存健康检查。

## 本地运行

```bash
npm install
npm run dev
```

访问 `http://localhost:3000`。天气由服务端通过 HTTPS 调用 Open-Meteo，并明确请求 ECMWF IFS 0.25°、CMA GRAPES Global 15 km 和 CAMS；浏览器不会接触提供方密钥。Open-Meteo 是 API 聚合与交付层，不是中国官方预警机构。默认开放端点仅适合非商业用途并受公平调用限制；商业部署应配置 `OPEN_METEO_API_KEY`，应用会自动改用 Open-Meteo customer weather 与 air-quality 端点。地图由 MapLibre GL 渲染，默认使用 CARTO / OpenStreetMap 栅格底图；可用 `NEXT_PUBLIC_MAP_STYLE_URL` 更换 MapLibre 样式。

## 验证

```bash
npm run verify
```

验证链路包含 ESLint、TypeScript、29 个气象/天文/提供方/API 边界测试、生产构建，以及 22 个 Playwright 浏览器流程。浏览器审计覆盖真实天气 API、全部七种摄影场景与三种天气工具、七个日期、逐日月亮变化、工具切换不导航/不重取数据、刷新与数据源降级、城市搜索与键盘操作、两种定位入口、地图点击/标记拖动/拒绝回滚/平移/缩放/归属信息、数据披露、失败恢复、404、健康检查和生产 CSP。24 次 Axe 扫描覆盖桌面与移动端的全部十种工具、搜索、错误和 404 状态；UI 审计同时检查关键文字字号下限、Compact 网格列数、贡献 hint、1440×900 首屏信息集合、方法披露交互、横向溢出、裁切、重复 ID 和未命名控件，并在 320×568 到 1920×1080 的八种代表性视口生成 187 张状态截图。

截图写入 `test-results/ui-audit/`。Playwright JSON 报告与截图数量由 `npm run verify:audit` 交叉核对，并生成 `test-results/audit-summary.json`，防止新增场景、失败结果或缺失视口被一个绿色退出码掩盖。

## 数据与概率边界

- ECMWF IFS 和 CMA GRAPES 分别评分；分歧越大、预报越远，置信度越低。
- CAMS 提供气溶胶光学厚度和 PM₂.₅。
- Open-Meteo 提供统一 HTTPS 接口、字段转换与归属信息，不是实况站、雷达或政府预警权威；恶劣天气应以[中国气象局预警](https://weather.cma.cn/web/alarm/map.html)为准。
- Astronomy Engine 根据定位点计算太阳、月亮与食象几何；天文事件可长期计算，但长期天气不可预测。
- 坐标更新有单实例的每 IP 突发保护；多实例部署仍应在网关或共享存储上配置全局配额。
- 霞光、雾景、月亮和星空的 0–100 是透明的启发式“机会指数”，还不是由大量实拍样本校准的统计概率。
- 云层分数是总云量；降雨分数是跨字段、跨模式的综合信号，不是降雨概率；彩虹分数是必要条件同时出现的潜势，不是确定性预测。
- 地图方位未计入山体/建筑遮挡；雾景尚未计入水体距离和精细地形；星空尚未计入光污染和银河构图。

完整数据调研见 [`docs/data-research.md`](docs/data-research.md)，摄影专业审查、缺口矩阵与实施路线见 [`docs/professional-photography-audit.md`](docs/professional-photography-audit.md)。

## 结构

- `components/weather-map.tsx`：MapLibre 生命周期、可拖动落点、太阳/月亮方位线。
- `components/glow-dashboard.tsx`：十工具注册表、共享一页工作区、七天时间带、食象事件带和拍摄时刻现场简报。
- `lib/weather.ts`：双模式 168 小时数据、事件窗口和降级处理。
- `lib/weather-analysis.ts`：云层、降雨和彩虹的纯计算器与输入置信边界。
- `lib/glow-model.ts`：霞光机会模型。
- `lib/photography-models.ts`：雾景、月亮和星空机会模型。
- `lib/astronomy.ts`：蓝调/金色/天文暮光、逐日月相、月升月落及本地可见食象。
- `app/api/forecast/route.ts`：中国坐标校验、定位点私有缓存与统一 API。
